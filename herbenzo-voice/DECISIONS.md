## Known issues
- **Latency (blocks good voice UX):** hosted NVIDIA endpoints give ~2–4 s median per turn without rails and ~5–6 s with rails (output rail adds up to the 3 s timeout), with spikes of 12–20 s. `GUARDRAILS_OUTPUT_ENABLED=false` saves the output-rail time. Options for M6: filler speech ("One moment"), a faster extractor model/provider for extraction only, or self-hosted NIM.
- The extractor sometimes misses `chief_complaint.summary`/`body_system` or a volunteered trigger (e.g. "worse after spicy food"), causing an extra question.
- Input guardrail is unavailable on roughly 60% of turns with the hosted NemoGuard endpoint; **pipeline/prod fail closed** (turn rejected). Intake-only demo still fails open. A self-hosted NIM would fix both reliability and latency.
- Rate limiting and metrics are per process: running more than one agent instance needs a shared store for both.
- Voice latency: a long first description takes ~13 s to answer (extractor + guardrail + responder + output rail + TTS on hosted endpoints).

## Open decisions for Shiva
1. Languages beyond English (Hindi/Telugu ASR+TTS availability not yet verified).
2. LLM provider per role (NVIDIA vs Claude vs Gemini).
3. Pilot user group (consumers, practitioners, researchers).
4. Paediatric intake (currently out of scope, `MIN_ADULT_AGE=18`).
5. Clinician review of `red_flags.yaml`, escalation and consent scripts before any external pilot.
6. Hosting and data residency (NVCF public endpoints vs self-hosted NIMs in India).
